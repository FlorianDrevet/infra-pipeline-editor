## Notes de requalification

- `APP-008` n'a pas necessite de refactor large supplementaire : le seam central existe deja et le finding etait devenu stale.
- `ARCH-003` n'a pas ete traite par split artificiel : le bon correctif etait de constater que `GenerationCore` est deja un noyau de contrats/helpers, puis de l'empêcher de regresser.
- `FRONT-005` etait mal scope : le vrai manque etait la couverture des ecrans critiques, pas l'absence d'un runner de test.
- `DB-008` a ete referme en hygiene de release plutot qu'en refactor de branche : aucun squash de sous-chaine EF n'est a forcer ici.
- `DB-014` et `DOM-011` ont ete requalifies : ils relevaient d'une architecture speculative non justifiee par un comportement defaillant courant.
- `API-009` et `APP-013` ont ete refermes sans sur-abstraction : le seam actuel suffit et un refactor large aurait surtout ajoute du bruit.
- `SEC-007` a ete referme par preuve executable : le comportement de log est deja couvert par la suite API sans reinjecter un logger custom dans `ErrorHandling.cs`.
- `APP-012` a ete referme par discipline d'abstraction : les helpers de regles partagées suffisent, une base class generique de validator n'apporterait pas de levier.
- `DB-015` a ete referme par lecture du modele EF : le convertisseur nullable generique existe deja et les usages repetes passent par lui.
