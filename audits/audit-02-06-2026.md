### DB-020 — `SubnetExistsAsync` viole la règle EF Core LINQ (`.Id.Value ==`)
- **Sévérité :** high
- **Statut :** NEW (BUG)
- **Fichier :** `src/Api/InfraFlowSculptor.Infrastructure/Persistence/Repositories/VirtualNetworkRepository.cs:44`
- **Constat :**
```csharp
var guidValue = subnetId.Value;
return await Context.Set<Subnet>()
    .AnyAsync(s => s.Id.Value == guidValue, cancellationToken);
```
Violation directe de la règle critique CLAUDE.md §9 : "Never `x.Id.Value == id.Value` — always `x.Id == id`". L'expression `.Id.Value ==` passe par un accès membre supplémentaire qui peut **ne pas être correctement traduit en SQL** par EF Core selon la configuration du converter. Le résultat peut être une requête incorrecte ou une évaluation client (LINQ-to-objects fallback) qui charge tous les subnets en mémoire.
- **Risque :** Requête SQL incorrecte → faux négatifs sur l'existence d'un subnet. Si EF Core évalue côté client, charge toute la table Subnets en mémoire à chaque appel.
- **Recommandation :**
```csharp
return await Context.Set<Subnet>()
    .AnyAsync(s => s.Id == subnetId, cancellationToken);
```

## SECTION 4 — Application / CQRS (APP)

### APP-015 — `Enum.Parse` sans protection dans AddSubnet et UpdateSubnet handlers
- **Sévérité :** high
- **Statut :** NEW (BUG)
- **Fichiers :**
  - `src/Api/InfraFlowSculptor.Application/VirtualNetworks/Commands/AddSubnet/AddSubnetCommandHandler.cs:40-43`
  - `src/Api/InfraFlowSculptor.Application/VirtualNetworks/Commands/UpdateSubnet/UpdateSubnetCommandHandler.cs:40-43`
- **Constat :**
```csharp
var delegation = request.Delegation is not null
    ? new SubnetDelegation(Enum.Parse<SubnetDelegation.Delegation>(request.Delegation, ignoreCase: true))
    : (SubnetDelegation?)null;
var privateEndpointPolicy = new PrivateEndpointNetworkPolicy(
    Enum.Parse<PrivateEndpointNetworkPolicy.Policy>(request.PrivateEndpointNetworkPolicies, ignoreCase: true));
```
Les validators `AddSubnetCommandValidator` et `UpdateSubnetCommandValidator` ne valident **pas** que `Delegation` et `PrivateEndpointNetworkPolicies` sont des valeurs d'enum valides. Un appel avec `"InvalidValue"` provoque une `ArgumentException` non capturée qui remonte jusqu'au global exception handler (500 interne) au lieu d'un 400 structuré.
- **Risque :** Comportement de crash visible pour le client. Exception non intentionnelle au lieu d'une erreur de validation explicite.
- **Recommandation :**
  1. Ajouter dans les validators : `RuleFor(x => x.Delegation).Must(v => v is null || Enum.TryParse<SubnetDelegation.Delegation>(v, ignoreCase: true, out _)).WithMessage("Invalid delegation value.")` et même chose pour `PrivateEndpointNetworkPolicies`.
  2. Ou utiliser `Enum.TryParse` avec fallback à une erreur `ErrorOr` dans le handler.

### APP-016 — N+1 potentiel dans `SetPrivateEndpointConfigCommandHandler`
- **Sévérité :** medium
- **Statut :** NEW
- **Fichier :** `src/Api/InfraFlowSculptor.Application/NetworkingProfiles/Commands/SetPrivateEndpointConfig/SetPrivateEndpointConfigCommandHandler.cs:40-56`
- **Constat :** Le handler charge le VNet **deux fois** : une fois via `resourceGroupRepository.GetByContainedResourceIdAsync` pour vérifier l'appartenance au projet (join implicite), puis une seconde fois via `virtualNetworkRepository.GetByIdReadOnlyAsync` pour vérifier l'existence du subnet. Double roundtrip base de données inutile.
- **Risque :** Performance dégradée. Chaque appel `SetPrivateEndpointConfig` génère 2 queries VNet au lieu de 1.
- **Recommandation :** Charger le VNet en une seule requête avec `GetByIdReadOnlyAsync` qui inclut le `ResourceGroup`, puis vérifier l'appartenance au projet à partir de cette entité.
